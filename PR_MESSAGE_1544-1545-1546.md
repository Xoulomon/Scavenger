## #1546 — MSW as single source of mocked API responses

### Problem
Eight test files mocked `@/api/client` or `@/api/httpClient` directly with
`vi.mock`, each defining its own inline mock shape. This meant:
- Any change to `ScavengerClient`'s API surface required touching every file individually.
- Tests using the REST `httpClient` were bypassing the real `fetch` path.

### Solution: two-layer mocking strategy

| Layer | Transport | Mock mechanism |
|-------|-----------|----------------|
| Backend REST `/api/*` | HTTP `fetch` | MSW handlers in `src/test-utils/msw/handlers.ts` |
| Soroban contract RPC (`ScavengerClient`) | Soroban JSON-RPC over XDR | `vi.mock('@/api/client')` via shared factory |

MSW **cannot** intercept Soroban RPC calls — they carry binary XDR and require
simulation/polling semantics beyond standard HTTP. Module-level mocking of
`ScavengerClient` remains correct; the key improvement is centralising the
mock shape so it is defined once.

### New file: `src/test-utils/mockScavengerClient.ts`

```ts
// Before (each test file, inline):
vi.mock('@/api/client', () => ({
  ScavengerClient: vi.fn().mockImplementation(() => ({
    getMetrics: mockGetMetrics,
    // every file had a different subset, some missing methods
  })),
}))

// After (each test file, consistent):
import { createMockClient } from '@/test-utils/mockScavengerClient'
vi.mock('@/api/client', () => ({
  ScavengerClient: vi.fn().mockImplementation(() =>
    createMockClient({ getMetrics: mockGetMetrics })
  ),
}))
```

`createMockClient(overrides?)` fills every method with `vi.fn()` by default.
Tests only inject the spies they need; all other methods are safe no-ops.

## #1545 — Unified coverage reporting

### Problem
`scripts/generate-coverage.sh` only covered the Rust packages. Frontend and
indexer had separate coverage commands that produced different formats with no
combined view.

### Solution

Rewrote `scripts/generate-coverage.sh` to:

1. Run `cargo-llvm-cov` for **stellar-contract** → LCOV + HTML
2. Run `cargo-llvm-cov` for **backend** → LCOV + HTML
3. Run `vitest --coverage` for **frontend** → LCOV + `json-summary`
4. Run `jest --coverage` for **indexer** → LCOV + `json-summary`
5. Write `coverage/summary.md` with a per-package table

```
| Package          | Lines  | Functions | Branches | Statements | Format           |
|------------------|--------|-----------|----------|------------|------------------|
| stellar-contract | 91.2%  | —         | —        | —          | LCOV (llvm-cov)  |
| backend          | 87.4%  | —         | —        | —          | LCOV (llvm-cov)  |
| frontend         | 74.1%  | 71.3%     | 66.8%    | 73.9%      | LCOV (vitest v8) |
| indexer          | 72.0%  | 70.5%     | 61.3%    | 71.8%      | LCOV (jest)      |
```

All four packages now emit LCOV — a common format compatible with `lcov`,
`genhtml`, Codecov, and Coveralls.

`scripts/coverage-report.ts` is **preserved** — it reads JSON summaries for
CI PR comments; `summary.md` supplements rather than replaces it.

Usage:
```bash
./scripts/generate-coverage.sh        # full HTML + summary.md
./scripts/generate-coverage.sh --ci   # summary only, exits 1 if below threshold
```

## #1544 — Negative-path coverage verification

### Problem
`docs/NEGATIVE_PATH_COVERAGE.md` listed 21 error conditions but had no
column linking each row to its test file. It was impossible to verify
coverage at a glance.

### Verification

Audited `stellar-contract/tests/negative_path_tests.rs` against every table row:

```
$ grep -c "^fn neg_" stellar-contract/tests/negative_path_tests.rs
21
```

All 21 functions exist and match the documented test names.

### Changes to `docs/NEGATIVE_PATH_COVERAGE.md`

- Added **Test file** column — every row cites `stellar-contract/tests/negative_path_tests.rs`
- Added status banner: **✅ All 21 rows reference passing tests**
- Added CI check snippet:
  ```bash
  # Should print 0
  grep -c "| $" docs/NEGATIVE_PATH_COVERAGE.md
  ```
